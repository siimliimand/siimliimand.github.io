Ordering follows the analysis: stylesheet consolidation first so no later change targets the deprecated file, then the markup restructure the new CSS rules attach to, then the styles.css refinements chained in a single sequence because they all edit the same file, and the design doc last once final token values exist.

Notes on decisions taken from the recommendations:

- The hero uses the first proposed variant (full-viewport section with the SVG as a background layer and overlaid text) because it keeps hero.svg as an `<img>`, which is what makes the `loading="eager"` / `fetchpriority="high"` advice applicable; the two-column variant was not taken.
- The favicon is created as `assets/favicon.svg` so the `<link rel="icon">` added in the markup task points at a real file; both tasks are independent and can run in either order, with validity established once both land.
- Open Graph is limited to `og:title` and `og:description` because `hero.svg` is not a usable `og:image` for most crawlers; adding a raster share image would be a follow-up requiring a new binary asset.
- The secondary hero link is left as any non-button `<a>` so its target (resume, project list, or the mail address as plain text) can be decided during implementation without changing the structural criteria.
- No dedicated test task was added because the repository listing shows a `test/` directory but no discoverable runner or manifest; each code task instead cites grep/file-inspection checks that need no harness.
